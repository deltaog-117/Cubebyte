## [Unreleased]

### Added
- Project scaffold with feature-first modules: `world`, `events`, `building`, `player`, `rendering`, `shared`, `app`
- `Cargo.toml` (edition 2024), `clippy.toml` and `scripts/check` (format check, clippy with warnings as errors, tests)
- Voxel types in `shared::voxel`: `BlockId`, `ChunkPos`, `WorldPos` and `LocalPos`, whose constructor rejects out-of-range coordinates
- `WorldPos::split`, using floor division so negative coordinates land in the correct chunk
- `Chunk`: a 16×16×16 flat block array with an O(1) empty check
- `World`: chunk map that changes only through `World::apply(&Event)`, rejecting stale events and never storing all-air chunks
- `shared::event::Event::BlockSet` with `inverse()`, so edits can be undone without a snapshot
- `events::log::EventLog`, an append-only event log
- Property tests for position splitting, chunk contents, undo of every event, and replay of a log into an equal world
- Criterion benchmarks for chunk reads and for placing and removing a block
- `shared::rng::Rng`: seeded xoshiro256++ (SplitMix64 seeding) with unbiased `below(bound)` and `fork(key)` for independent per-key streams
- Tests that pin the generator's output for known seeds, so any change to the stream fails loudly
- `shared::clock::FixedClock` and `Tick`: integer-time fixed timestep with carry-over and a cap on catch-up steps per advance
- Property tests for the clock (frame splitting never changes the tick count) and the generator (determinism, bounds, fork independence)
- Criterion benchmark for `Rng::next_u64` and `Rng::below`
- `README.md` with the project description, status, tech stack (Rust + `wgpu` + `winit`), structure and test commands
- `world::generation::TerrainGenerator`: seeded, deterministic terrain from hand-written 2D Perlin noise (four octaves), with grass, three dirt blocks and stone below; heights stay within `MIN_HEIGHT..=MAX_HEIGHT`
- `World::insert_generated` and `InsertError`: install generated chunks as the baseline without logging events, and refuse to overwrite a loaded chunk
- `BlockId::STONE`, `DIRT` and `GRASS` constants, and `LocalPos::all()` to iterate a chunk in index order
- Tests that pin terrain heights for known seeds, check there are no cliffs between neighbouring columns, and check chunk layers across chunk borders
- Criterion benchmark for generating a surface chunk and a sky chunk

- `simulation::persist`: a versioned binary file (`MCIT`, version 1) for the intent log. Each run of one intent on consecutive ticks is a single 19-byte record, so standing still for an hour costs one record; `encode`, `decode`, `save` (via a temporary sibling file) and `load`. A damaged file is refused: a cut run, an empty run, a run past the last tick, a walk axis outside -127 to 127, a jump flag other than 0 or 1, or ticks that go back

- `simulation::stream::IntentStream`: the intent log written to disk while the game runs. Settled entries are appended to the session file as runs once 2048 gather, so memory stays small and a crash loses a minute or two of play at most; the file is created on the first write, a failed write is cut back and retried later with nothing dropped, and `finish` writes the rest and syncs

- `simulation::persist::decode_recovering`: reads a session file cut short by a crash or power loss, keeping the whole runs before the cut and reporting the bytes left over

- `simulation::action::Action` (break, place, craft, eat) and an action list in `IntentLog` (`record_action`, `actions`, `actions_at`); `IntentStream::record_action` writes them to the session file with the walking steps, and `Replay::actions_at` gives the ones due on a tick
- `inventory::service::gather_events_at` and `place_events_at`: break or place at a named position instead of along a look direction; a break needs a block there, a place needs an empty cell
- A replay now performs the recorded breaks, placements, crafts and meals on their ticks, and the new session records them again; keys and mouse do not act during a replay
- `Action::Strike(ActorId)`, `Action::Rewind` and `Action::Redo`: hits on a mob and the `Z`/`Y` rewinds are saved in the session file (kinds 5, 6 and 7) and performed again by a replay; a strike names the zombie it hit, so it is refused if that zombie is gone

- `combat::service::hit_events` and `respawn_events`: the events for a hit and for starting over (meters refilled, pack emptied)

- `Event::MobSpawned`, `MobRemoved` and `MobHealthChanged`, with `shared::event::MobId`: a mob appearing, leaving (killed, dropped or cleared at a respawn) and gaining or losing health by the points it really moved; a spawn and a removal are each other's inverse, and a removal remembers the mob's health so an undo brings it back as it was
- `mobs::model::Mobs`, the store of every living mob by id, changed only through `spawn`, `remove` and `shift_health`; a removal checks the mob's id and health but not where it stands, since walking is not an event
- `mobs::service::strike_events`, `spawn_event`, `despawn_event` and `clear_events`: the events for a hit (only the health really lost, then a removal when none is left), a new zombie, a dropped one and clearing every mob
- `events::apply::Stage` holds the mobs, and `StageError::Mob` refuses a mob event for a mob that is missing, already there, or whose health differs
- Event log format version 6: tags 11 to 13 for the mob events. Older files are still read; a restart does not bring mobs back, since only block events replay into chunks
- `ActionKind::Redo` and event log format version 7 (tag 14 ends a redo): `Y` is logged as its own kind of action, which rewind treats like an edit. Files up to version 6 are still read; a redo in an older file reads as a plain edit
- `events::redo::RedoStack::from_log`: the redo stack is rebuilt from the log at startup (a rewind pushes, a redo pops, an edit or a respawn empties it), so what `Z` undid can still be brought back by `Y` after a restart

- `Command::SpawnMob`, `Permission::Spawn`, `Denied::TooManyMobs` and `MAX_MOBS` (8): a script can add a zombie in the open, in range, while fewer than 8 mobs are alive; it is an `Event::MobSpawned`, logged and undone like any other command

- Script costs: a `fuel` item (stack of 64) and a recipe for it (2 stone and 1 grass make 2 fuel). Each accepted script command burns fuel from the pack (teleport 2, give 4, set block 1, spawn 5) and starts a wait before its kind may run again (2 s, 5 s, 0.2 s, 10 s); a refused command costs nothing and starts no wait

- Keys `X` (zone rewind around the player, radius 8) and `V` (cycle how far back: 1, 3, 10, 30, 100 actions); the title shows the choice

- `recipe <name> [take|make <item> <count> ...]` command: with steps it makes a player recipe at once (fair recipes only, checked by `RecipeProgram::try_new`), without steps it opens the recipe editor under that name; the command line holds up to 72 characters now

- `logic::model::Trigger` and `PlayerAction`: a rule can fire right after the player breaks, places, crafts, eats or hits, optionally only if its test holds; `Rules::add_with`, `set_trigger` and `due_on`; the rules panel gains "next trigger" and "action rule: use its test or not"
- `programs.nib` format `nib 2`: `on <action>` lines for action rules and `script <name>` sections; `nib 1` files still load
- `Event::MobMoved` and `Mobs::move_to`: a mob's walk from one spot to another, with a stale-position check and an exact inverse
- `events::walk`: `checkpoints` (the move events that record where the player stood at each edit and where a hit or removed mob stood) and `bridged` (a move in front of a rewind or redo that takes the player to where the edit left them)
- `EventLog::player_spot`, `mob_spot` and `forget_spots`: where the log last put the player and each mob, worked out as events are pushed and forgotten after a load
- `logic::react::reactions` and the rule triggers `hurt`, `respawn` and `appear` (`PlayerAction::{Hurt, Respawn, MobAppears}`): worked out from the events of passive actions and respawns

- Event log version 8: tag 15 for a mob's move; older versions still load
- Tests: a move event and its inverse (property), a save and reload of mob moves (property), checkpoints and bridges, a rewind and redo with the player walking between them, and rewinding and redoing every edit with random walks in between (property)

- `blueprints`: a blueprint of rules, recipes and one small build as text (the programs-file grammar plus a `blueprint <name>` section), read all or nothing, refusing text over 32 KiB before reading it; `capture` turns the 9×8×9 blocks around the feet into a build of at most 64 blocks

### Changed
- `Z` and `Y` also move the player: `Z` walks them to where the edit left them and then to where it found them, and `Y` is its exact opposite, so rewinding works wherever the player has walked since; every player edit logs one more event (where the player stood); a replay of a track recorded before this that used `Z` drifts after the first `Z`
- A player move to the spot where the player already stands no longer stops their fall
- `programs::file::write` writes `nib 3`; `PlayerAction` has three more kinds
- The ready-made scripts `tower`, `hop`, `stock` and `summon` are programs now and produce the same commands as before
- `ScriptRun` takes its commands from a flat list or from a program; a program reads the world through `ask` when it reaches an `if`
- The `T` panel lists only scripts that need no aim; the title shows `script name (n done)`
- The summary of the `zone` command is shorter, so the command table fits the smallest window (320 pixels wide)
- `app` spawns, hits, kills and drops zombies through `events::apply::apply_all` as passive events, and clears the mobs in the respawn action, so `Z` still steps over them; `Running` holds a `Mobs` store instead of one `Option<Zombie>`, and a mob's id is also its actor id in the intent log
- `mobs::service::strike` is replaced by `strike_events`, and `aimed_at` by `aim_distance`, which returns how far the hit is so a click picks the nearest mob
- The intent file is now version 3, which adds the strike, rewind and redo action kinds. Versions 1 and 2 are still read unchanged
- `Z`, `Y` and a left click on the zombie now go through the same `perform` path as breaking and placing, so they are recorded when they worked and nothing else is
- The intent file is now version 2: every record starts with a tag byte (run or action). Version 1 files are still read unchanged
- `app` aims a click by working out the target block first and then doing the action at that position, the same path a replay uses
- `app` writes intent tracks through `IntentStream` into `intents/NNNN.mcit`, one file per session, instead of replacing `intents.mcit` on exit; `simulation::persist` keeps the same format (version 1) and its `save` and `load`
- `app` sends breaking, placing, crafting and eating through `events::apply::apply_all` and logs the events, so the pack changes only through the one door and rewind can see these changes; the old direct functions remain. Hunger is still restored outside the events
- `shared::body::Intent` moved to `shared::intent` (still re-exported from `shared::body` and `player::service`) and its `walk` is now a `Walk` of whole numbers instead of a `Vec2`. Direction is rounded to about 0.45 degrees and speed to under 0.4%; a player step still costs about 180 ns
- `player::model::Player` wraps a `shared::body::Body`; `player::service::step`, `collides`, `Intent` and the speed constants keep their paths and behaviour. A step still costs about 181 ns
- `app` spawns a zombie 12 to 20 blocks away ten seconds after the start, after each kill and after each death; a left click on the zombie hits it instead of breaking the block behind it. Free flight does not stop it
- `app` starts the player walking on the terrain and moves it on the simulation tick; the camera follows its eyes and Space jumps. Free flight remains on `F`
- `app::run` streams chunks around the camera (radius 4, at most 8 loaded per frame) instead of generating a fixed 9×9 grid; edited chunks come back with their edits replayed from the log
- `Renderer::add_mesh` is now `Renderer::set_mesh(chunk, ..)`: meshes are kept per chunk, so one chunk can be replaced or removed
- `app` loads `world.mcel` at startup and saves it on exit when the world was edited; a save made with another seed stops the game instead of being overwritten
- The renderer reads block colours from `blocks::registry` instead of its own `match`
- `app` advances a `Simulation` every frame (20 steps per second, at most 5 per frame); nothing runs on a step yet
- `SolidBlock::try_new` accepts only defined solid blocks, so an ID with no definition is no longer placeable (it used to be accepted when not air)
- Left click now keeps the broken block's item, right click needs one of the selected block in the inventory, and a full inventory leaves the block standing
- `app` loads `inventory.mcin` at startup, saves it on exit when it changed, and shows health, hunger and item counts in the window title
- Starvation now kills: the old floor of 1 health is gone, and dying in `app` respawns the player at the start with full meters and an empty pack; the window title counts deaths
- `items::registry::ItemDef` gains `restores_hunger`, and `items::registry::ids()` lists every item; the window title lists all items instead of a fixed three
- Escape closes the crafting panel first and quits only when it is closed; the pointer is released while the panel is open and mouse look pauses
- `EventLog` keeps the per-chunk index for block events only; `World::apply` ignores events that change no blocks, so a whole log can still be replayed into a world
- `events::persist` writes version 2 and reads versions 1 and 2; records are no longer all the same length
- `events::persist` writes version 3 (tags 4 and 5 mark the end of an edit and of a rewind) and reads versions 1 to 3; saves older than version 3 have no action ends, so their history cannot be rewound
- `app::Running::commit` logs each applied list as one edit
- `events::persist` writes version 4 (tag 6 holds a base block) and reads versions 1 to 4; `events::replay::replay_chunk` applies a chunk's base blocks before its events. Version 4 files cannot be read by older builds
- The zombie takes its recorded step during a replay and decides for itself once the session has none; `F` (free flight) is ignored during a replay, because a flight leaves no steps in the track
- `eat_events` now includes the hunger the meal gives, so eating is a single all-or-nothing change of slots and hunger
- `app` logs the hunger drain and a zombie's hit as passive actions, and a death as a respawn action (meters, pack and a move to the spawn point); the redo stack is cleared on death
- `events::persist` writes version 5 (tags 7 and 8 hold the meter events, tags 9 and 10 end a passive action and a respawn) and reads versions 1 to 5
- `scripting::service::run` takes the `next_mob` id counter as a last argument, so a spawn command can hand out ids that are never reused; it moves on only when a spawn is accepted
- `events::persist` writes version 7; the unknown-tag test now uses tag 15, since tag 14 is the redo end
- `app` rebuilds the redo stack from the log at startup and logs `Y` as a redo
- `scripting::service::run` takes a `Pace` (the tick and the cooldowns) and logs each accepted command as its own edit together with the fuel it burned, so `Z` takes a scripted command back whole and gives the fuel back
- `scripting::service::ask` takes the player's `Facing` as an argument, since the camera is not part of the game state it reads
- `ui::layout` lays both panels out with one shared function; `ui::draw` draws the script panel with `script_overlay`
- Escape closes whichever panel is open; mouse look pauses while either is open
- `simulation::persist` writes version 4 (kind 8 holds a script command) and reads versions 1 to 4
- `simulation::persist` writes version 5 (kind 9 holds a zone rewind) and reads versions 1 to 5
- `Running::script_command` returns why a command was refused (`Result<(), Denied>`) instead of a bare yes or no, and `Running::perform` reports whether the action worked; typed script commands run at the script point of the tick
- `Running::rewind` pays the rewind price in the same all-or-nothing batch as the undo and refuses, with a note in the title, when the pack cannot pay; a redo gives the price back, since it is the exact inverse
- `EventLog` equality ignores records folded away and not yet taken, which are output waiting to be written
- `app` writes `world.mcea` on exit, after the world file is saved
- The shader reads the camera position, fog range and sky colour from the camera uniform and blends terrain and mobs towards the sky colour with distance; the interface has its own fragment entry and is not fogged; `app` sets the fog from the load radius
- `Running::rewind` clamps the meter changes of an undo against the current meters before it prices and applies the rewind
- `chunks_to_remesh` returns every chunk holding a block in the 3×3×3 cube around an edit, not only the six face neighbours, because corner shading reads diagonal blocks
- `GpuVertex` has a third field and the vertex layout a third attribute; `Vertex` in the mesher has an `occlusion` field and `neighbor` takes a step in blocks instead of a face
- `prune_sessions` deletes a session's starting-world folder together with its file
- A session that began as a replay leaves the live `world.mcel`, `world.mcea`, `inventory.mcin` and `stats.mcst` untouched on exit, since it played in a copy of an old world
- `Rules::add` takes an `Anchor`, `Rule::anchor` returns one, and `Rules::due` takes a function that turns an anchor into the cell it stands for
- The rules panel lists each rule's anchor and gains a "next anchor" row
- `ItemDef` gains a `worth` field
- `programs::file::write` takes the script edits too, and `Programs` has a `scripts` field; the game writes `nib 2`
- `command::model::{Request, Value}` and `command::plan::Plan` are no longer `Copy`, since a recipe line carries a checked recipe
- `ui::layout::script_panel` and `hack_panel` take the script edits, so a row shows what the script really costs
- Polling rules ignore action rules, and the rules panel line shows what sets a rule off

- `shared::body::step` and `collides` take a `Terrain` (the world as tiny cubes a quarter of a block wide) instead of a closure; a closure of whole blocks still works, and on whole blocks the numbers are exactly the old ones
- Meshing: a plain block no longer hides its face against a moulded neighbour, and moulded blocks have their own pass that draws tiny cubes
- Breaking a moulded block yields its material
- `crafting::registry::RECIPE_COUNT` names the length of the recipe table; the crafting panel and the craft key skip shaped recipes

### Fixed
- Undoing a meal was refused when hunger had drained below what the meal gave (for example eating at 0, a drain to 3, then `Z` asking for -4); the undo now stops at 0
- The command table was 4 pixels wider than a 320-pixel window, so its right edge was cut off in the smallest windows
- Rewinding or redoing an edit in a chunk that had been unloaded was refused, and undoing a break there would have left a one-block chunk that stopped the real chunk from loading. `app` now loads every chunk a rewind or redo touches (generated terrain plus its logged edits) before applying it
